# ai-personal-profile

> 跨 AI 共享的个人档案 · 单一事实来源（Single Source of Truth）

本仓库用于在**不同 AI 助手之间共享同一份个人档案**。任何 AI 在为你工作时，都可以先读取本文件，快速了解你的背景、习惯、偏好与目标，避免每次从零开始解释自己。

- 仓库地址：https://github.com/ouchengzhi/ai-personal-profile
- 维护人：仓库所有者
- 更新频率：随用随更，重大变化单独提交
- 隐私提示：这是**公开仓库**，请勿填写身份证号、住址、电话、密钥等敏感信息。

描述你如何安排时间、如何推进任务、如何学习新技术。

**示例条目：**

## 3. 沟通风格偏好

告诉 AI 你希望它如何与你对话。

**示例条目：**

- 语言：简体中文；专有名词保留英文原文
- 风格：直接、结论先行，先给答案再给理由；避免空泛客套
- 长度：默认简短；复杂问题再展开，并提供可复制的清单或代码
- 反馈方式：不确定时先说明假设并给出选项，不要猜测后直接执行
- 禁止事项：不要编造数据或来源；不确定的地方明确标注「未核实」
- 称呼：希望被如何称呼（例如直接叫名字）

## 7. 维护与版本记录

### 待办跟踪

- 使用本仓库的 **Issues** 记录待办：补充档案、修正信息、新增项目条目。
- 可用模板新建 Issue：
  - `Profile update`（档案更新）
  - `New project entry`（新增项目）
  - `Todo`（通用待办）
- 建议标签：`profile`、`todo`、`project`、`question`、`urgent`。
- 需要看板式管理时，可在仓库 Settings → Features 中启用 **Projects**，把 Issue 拖入看板。
- 提交流程与提交信息约定见 [CONTRIBUTING.md](CONTRIBUTING.md)，实质变更记录见 [CHANGELOG.md](CHANGELOG.md)。

### 版本记录与回退

Git 原生保存每次修改，全部可追溯、可回退：

```bash
# 查看修改历史
git log --oneline --decorate

# 查看某次提交改了什么
git show <提交哈希>

# 回到某个历史版本（保留后续提交，生成一次反向提交）
git revert <提交哈希>

# 临时查看旧版本内容（不改动当前分支）
git show <提交哈希>:README.md

# 强制把分支指针移回旧提交（谨慎，会影响协作者）
git reset --hard <提交哈希>
```

**提交约定：** 每次只改一个章节，提交信息写清楚改了什么，例如 `docs: 更新沟通风格偏好`。
